# Open-HotSpot

[English](README.md) · [العربية](README.ar.md) · [简体中文](README.zh-CN.md) · [한국어](README.ko.md) · [Deutsch](README.de.md) · [日本語](README.ja.md)

Open-HotSpot هو نظام محلي لبوابة الدخول وإدارة الشبكات على OpenWrt، مبني حول
[openNDS](https://opennds.readthedocs.io/) ويُدار من خلال LuCI.

> **الحالة: مرشح قبول قبل الإنتاج.** توجد نواة تنفيذية واختبارات آلية واسعة،
> لكن بوابات الراوتر الفعلي لم تُغلق بعد. لا يُعامل `1.2.0-r112` كخط أساس
> إنتاجي قبل اكتمال الأدلة الميدانية.

## الفكرة

يحتفظ Open-HotSpot بالهوية والسياسات والمحاسبة والإدارة محلياً على راوتر
OpenWrt، بينما يبقى openNDS مسؤولاً عن بوابة الدخول وفرض حركة المرور. لا يحتاج
المشروع إلى RADIUS أو خدمة سحابية أو قاعدة بيانات خارجية.

## ماذا يقدم؟

| القدرة | الوصف |
|---|---|
| الحسابات | أسماء مستخدمين وPIN محلية |
| الأجهزة | عدة أجهزة للحساب مع دورة حياة واضحة وإعادة إسناد آمنة |
| القسائم | استرداد ذري لمرة واحدة |
| الملفات | حدود الوقت والبيانات والسرعة والفترة وعدد الأجهزة |
| الحصص | محاسبة تراكمية حسب الفترة مع قطع دخول جديد عند الاستنفاد |
| لوحة المتابعة | حالة openNDS الحية مع سجل SQLite |
| المصادقة | محلية، دون RADIUS أو سحابة |
| LuCI | واجهة إدارة أصلية لـ OpenWrt |
| البوابة | قوالب عربية RTL وإنجليزية مثبتة محلياً |

## كيف يعمل؟

```text
العميل
  │
  ▼
بوابة openNDS
  │
  ▼
FAS المحلي ── تحقق الحساب/PIN ── SQLite
  │
  ▼
تفويض openNDS
  │
  ▼
فرض السياسة ── BinAuth ── المحاسبة في SQLite
  │
  ▼
إدارة LuCI / RPC
```

الحد المعماري مقصود: openNDS هو محرك فرض السياسة، وOpen-HotSpot يملك الهوية
والسياسات والمحاسبة والإدارة. BinAuth معالج أحداث ولا يستدعي `ndsctl`.

## الهيكلة

```text
starter-kit/   حزمة LuCI والملفات التي تُثبّت على الراوتر
tools/         البناء، التحقق، الإعداد، التشخيص، والنشر المحروس
tests/         اختبارات Python وعقود Shell وواجهات التكامل
docs/          مصدر الحقيقة، المعمارية، القبول، التشغيل، والأرشيف
specs/         المواصفات والقرارات وخطة التنفيذ
```

## ما أُنجز وما بقي؟

| المجال | الحالة |
|---|---|
| قاعدة البيانات والحصص والقسائم والعقود | Tested محلياً |
| مسار البوابة → FAS → openNDS → BinAuth | Verified على المسار المستهدف |
| اتجاه العدادات والقطع الأصلي للحصة | Pending Hardware Validation — T006 |
| الاستعادة بعد إعادة التشغيل واحتواء الفشل | جزئي — T011/T086 |
| الإعداد القابل للتكرار بعد المقاطعة | مفتوح — T052/T087 |
| خط أساس إنتاجي | محجوب حتى إغلاق T090 |

## أولويات المساهمة

- إغلاق T006 بقياس الرفع والتنزيل وحدود القطع على عميل حقيقي.
- إغلاق T011/T086 باختبارات إعادة التشغيل والاستعادة وتكرار callback واحتواء الفشل.
- إغلاق T052/T087 على راوتر نظيف مع مقاطعة الإعداد وإعادته.
- إكمال T088/T090 ومصفوفة قبول الإصدار.
- تنفيذ والتحقق ميدانياً من Boundary 1/2؛ عقد OP-203 الحالي يثبت عدم تصادم
  المعرفات فقط، ولا يثبت عزل daemon أو FAS أو المحاسبة أو nftables.

ابدأ من [`CONTRIBUTING.md`](CONTRIBUTING.md)، و[`حالة المشروع`](docs/project-status.md)،
و[`بوابات الإصدار`](docs/release-gates.md). لا تُحوّل لقطة أو mock أو اختباراً
محلياً إلى قبول عتاد.
