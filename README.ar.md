# Open-HotSpot

Open-HotSpot هو نظام محلي لبوابة الدخول وإدارة الشبكات على OpenWrt، مبني حول
openNDS ويُدار من خلال LuCI.

يوفر حسابات محلية، وأجهزة متعددة لكل حساب، وقسائم، وملفات سرعة، وحصصاً
تراكمية، وتحكماً تلقائياً بالوصول، وسجل استخدام، ولوحة متابعة؛ دون الحاجة إلى
RADIUS أو خادم خارجي أو خدمة سحابية.

> **الحالة: مرشح قبول قبل الإنتاج.**
>
> توجد نواة تنفيذية واختبارات آلية واسعة، لكن بعض بوابات اختبار الراوتر الفعلي
> ما تزال مفتوحة. راجع [`docs/project-status.md`](docs/project-status.md)، ولا
> تعتبر الإصدار الحالي خط أساس إنتاجياً قبل إغلاق بوابات الإصدار.

## لماذا Open-HotSpot؟

إدارة شبكة hotspot صغيرة لا ينبغي أن تتطلب اشتراكاً سحابياً أو خادم مصادقة
منفصلاً. يحتفظ Open-HotSpot بالهوية والسياسات والمحاسبة والإدارة داخل راوتر
OpenWrt، ويترك لــ openNDS مسؤولية بوابة الدخول وفرض حركة المرور.

## ماذا يقدم؟

| الوظيفة | الوصف |
|---|---|
| الحسابات | اسم مستخدم وPIN محليان |
| أجهزة متعددة | ربط عدة أجهزة بالحساب نفسه |
| القسائم | استخدام ذري لمرة واحدة |
| الملفات | سرعة وحصة وفترة وحد أقصى للأجهزة |
| الحصص | حساب الاستخدام التراكمي حسب الفترة |
| القطع التلقائي | رفض الدخول عند استنفاد الحصة |
| لوحة المتابعة | حالة openNDS الحية مع تاريخ SQLite |
| المصادقة المحلية | دون RADIUS أو سحابة أو خادم خارجي |
| LuCI | واجهة إدارة أصلية لـ OpenWrt |
| العربية | قالب عربي RTL وقالب إنجليزي |

## كيف يعمل؟

```text
العميل
  │
  ▼
بوابة openNDS
  │
  ▼
FAS المحلي في Open-HotSpot ── تحقق الحساب/PIN ── SQLite
  │
  ▼
تفويض openNDS موثق
  │
  ▼
فرض openNDS ── أحداث BinAuth ── المحاسبة في SQLite
  │
  ▼
إدارة LuCI / RPC
```

الحد المعماري مقصود: openNDS هو محرك فرض السياسات، بينما يملك Open-HotSpot
الهوية والسياسات والمحاسبة والإدارة. وBinAuth معالج أحداث ولا يستدعي `ndsctl`.

## خط أساس الاختبار الحالي

```text
الراوتر:       Linksys EA8300
OpenWrt:       25.12.5
الهدف:         ipq40xx/generic
openNDS:       10.3.1-r3
Open-HotSpot:  1.2.0-r60
```

يُكتشف عنوان الإدارة من إعداد LAN الحالي، ولا يدخل عنوان ثابت في عقد FAS.
ويُستخدم الإقلاع ثنائي القسم كمسار تراجع A/B، وليس كمخزن مشترك لبيانات
التطبيق.

## التثبيت والبدء

استخدم [دليل قبول الراوتر المعاد ضبطه](docs/factory-reset-acceptance-runbook.md)
على جهاز قابل للتراجع؛ فهو يغطي القسمين، ومفاتيح SSH المنفصلة، والعناوين
المكتشفة، والتحقق من الحزمة، واستعادة الإعداد، وأدلة الاختبار.

بعد تثبيت APK موثقة على الراوتر المرشح:

1. افتح **Services → Open-HotSpot → Setup**.
2. شغّل فحص ما قبل التعديل وتهيئة الأساس.
3. أنشئ ملفاً للسرعة والحصة والفترة وحد الأجهزة.
4. أنشئ حساباً وسجّل جهاز العميل.
5. صِل هاتف الاختبار بشبكة Open-HotSpot، وليس بواي فاي الراوتر العلوي.
6. افتح البوابة، سجّل الدخول، وتابع الجلسة من LuCI.

لا تستخدم عنوان راوتر ثابتاً في السكربتات أو الوثائق، وافصل شبكة الإدارة عن
شبكة العملاء/إنترنت الأشياء بشبكات غير متداخلة.
